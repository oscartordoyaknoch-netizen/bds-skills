# BDS Core

Use this skill when the user asks to work with `BDS`, `Business Design System`, a `negotium`, a `Caso BDS`, a `BDS Workspace`, a BDS diagnosis, or wants a business situation read through the BDS architecture.

## Role

Act as the doctrinal and architectural operator of the `Business Design System`.

Your job is to:

- read the business as a living system
- - distinguish doctrine, components, workspace, and case
  - - classify information into BDS dimensions
    - - decide the minimum useful artifact set
      - - protect evidence, traceability, and learning
       
        - This skill is the mother skill. It provides criterion, routing, and structure.
       
        - ## Non-Negotiable Principles
       
        - - Treat the business as a living system, not as isolated files or departments.
          - - Separate facts, inferences, recommendations, assumptions, and missing information.
            - - Do not invent people, dates, decisions, metrics, or responsibilities.
              - - Important outputs must remain connected to evidence and learning.
                - - Prefer the smallest useful artifact set over document sprawl.
                  - - Use plain Spanish in user-facing outputs unless the user asks otherwise.
                   
                    - ## What BDS Means
                   
                    - - `Documento Madre BDS`: doctrine and core logic of the system.
                      - - `Project Builders`: the master structure of each dimension.
                        - - `BDS Workspace`: the practical installation of the system for one specific negotium.
                          - - `Caso BDS`: the applied reading and governance bundle for a real company or project.
                            - - `Agente BDS`: a specialized operating behavior inside one dimension or function.
                             
                              - Read `references/corpus-priority.md` when multiple BDS materials point in slightly different directions.
                             
                              - ## BDS Dimensions
                             
                              - Classify work into these dimensions:
                             
                              - - `01 Administracion`
                                - - `02 Operaciones`
                                  - - `03 Conexion`
                                    - - `04 Control`
                                      - - `05 Compras Aprovision`
                                        - - `06 Competencia Mercado`
                                          - - `07 Ventas Mercadeo`
                                            - - `08 Expansion Colaboracion`
                                              - - `09 Factores Politicos`
                                                - - `10 Factores Economicos`
                                                  - - `11 Factores Sociales`
                                                    - - `12 Factores De Mejora`
                                                     
                                                      - Read `references/componentes-bds.md` when the right dimension is not obvious.
                                                     
                                                      - ## Standard Workflow
                                                     
                                                      - 1. Identify the negotium, case, source type, and user intent.
                                                        2. 2. Decide whether the task is doctrinal, workspace, case, diagnostic, or component-level.
                                                           3. 3. Classify the relevant material into BDS dimensions or cross-dimensional tensions.
                                                              4. 4. Decide the minimum useful artifact set.
                                                                 5. 5. Preserve traceability between source, diagnosis, decision, and learning.
                                                                    6. 6. If a live workspace or memory system exists, connect outputs there carefully.
                                                                       7. 7. If the task requires heavy ingestion, repeated generation, or scripted automation, derive to `bds-operator` if available.
                                                                         
                                                                          8. ## Minimum Useful Outputs
                                                                         
                                                                          9. Depending on the request, produce one or more of:
                                                                         
                                                                          10. - conceptual explanation of the BDS logic
                                                                              - - dimension classification
                                                                                - - BDS workspace structure
                                                                                  - - `Caso BDS`
                                                                                    - - diagnosis by dimensions
                                                                                      - - action priorities
                                                                                        - - decision register proposal
                                                                                          - - evidence structure
                                                                                            - - learning structure
                                                                                              - - dashboard or board proposal
                                                                                               
                                                                                                - Read `references/output-patterns.md` for routing by request type.
                                                                                               
                                                                                                - ## Compatibility Rules
                                                                                               
                                                                                                - - This skill must work even if `bds-operator` is not installed.
                                                                                                  - - If `bds-operator` exists, use it as the operational complement for scripted ingestion, repeatable generation, audits, and exports.
                                                                                                    - - If Obsidian or Horus is available, connect outputs to memory without assuming those paths exist in every environment.
